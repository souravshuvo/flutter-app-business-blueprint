Double-click this HTML file to open it, then press a Copy button. Use these prompts from the actual game repository task.

Best workflow: run one phase at a time. If a phase finds blockers, fix them before moving to the next phase. Do not queue P2-P6 together. One prompt should have one job, one output, and one verification target. For new unpublished games, package name should follow com.childhood.<game_slug>. Fast mode: skip pub get, run, build, full analyze/test, Gradle, install, emulator, and release packaging unless essential. Standing authority is already granted for all required production v1 work; do not ask for approval. Pro mode: do not accept generic dashboards, forced level lists, dead menus, weak sound triggers, or boring prototype gameplay. Feel loop: after P2/P2B and P3, use screenshots, recording, or manual play notes for one visual gameplay iteration before ads/store work. 95% gate: no real visual/play evidence means no 95% claim. Score 95-100 to pass; 85-94 means iterate; below 85 means rescue.
Assigned flow: P1 audit/scope -> P2 core gameplay -> P2B pro hub/game feel -> P3 content/replay -> P2C visual playtest iteration -> P4/P5/P6 monetization, assets, release gate. If P2C says the game still feels weak, go back to P2B or P3 before ads.
